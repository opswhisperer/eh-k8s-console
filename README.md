A web console for the
[ExtraHop Kubernetes integration](https://docs.extrahop.com/current/integrations-kubernetes/).
It runs in your cluster next to the integration and lets you:

- change the integration's settings safely
- keep the sensor certificate right
- see and control what traffic is mirrored
- read the forwarders' logs
- get alerted when something breaks

It works with both the manifest generated by the sensor and the official Helm chart.

## Features

- **Overview:** the path from your cluster to the sensor in one view. It shows the forwarders, the Geneve traffic link, the metadata and session-key TLS links, and the sensor certificate, each with its health, followed by every problem found and how to fix it.
- **Settings editor:**
  - **Typed fields** with inline docs for every ConfigMap key, the integration Secrets (write-only) and image tags.
  - **Knows what reads what:** it works out which workload reads which setting from the manifests themselves.
  - **Linked args:** it keeps the session-key forwarder's `-server` / `-server-name-override` args in step with the ConfigMap.
  - **Key pairs:** the coordinator and forwarder key pairs are read-only, with a check that each private key matches its public key.
- **Review before apply:**
  - **Before anything changes:** every change shows its field changes, a diff, the exact restarts it needs, and the problems it would create or fix.
  - **Dry-run:** the change is checked by the API server first, so admission policies apply.
  - **Apply:** optimistic concurrency, and only the workloads that read a changed value restart.
  - **History:** every change is recorded with one-click undo. Secret values are never stored.
- **Sensor certificate:**
  - **Drift checks:** compares `sensorCert` with what the sensor presents, verified the way the forwarders verify it, and tells a harmless renewal from a broken chain.
  - **Updating it:** refresh from the sensor (CA chain only, so it survives renewals), paste certificates, or keep it in sync automatically.
  - **Details:** [docs/certificates.md](docs/certificates.md).
- **Traffic filtering:**
  - **Presets and lists:** presets, namespace pickers, and a list of every `extrahop.com/traffic-mirror-rule` annotation in the cluster.
  - **Annotation editing:** for pods (by name or label selector), workload templates and nodes.
  - **Preview:** an optional "what gets mirrored" preview, once you configure your version's evaluation order.
  - **Details:** [docs/filtering.md](docs/filtering.md).
- **Logs:**
  - **Live viewer:** live, merged logs from every integration pod, filtered by component, pod, level and text.
  - **Recurring errors:** grouped by normalized message.
  - **Ignore rules:** add one from any line, preview it, then view what's hidden.
  - **Events:** the integration's Kubernetes events alongside the logs.
- **Alerts:**
  - **Metrics:** Prometheus metrics, ready-made alert rules, and a Grafana dashboard.
  - **Notifications:** Kubernetes Events, and webhooks (Apprise, Slack, JSON) that fire only when a problem starts or ends.
  - **Details:** [docs/alerts.md](docs/alerts.md).
- **Sign-in:** OIDC, local users, API keys or an authenticating proxy, in any combination, with viewer, operator and admin roles. See [docs/auth.md](docs/auth.md).
- **Export:** manifests or a Helm values file, for the live state or a pending change (GitOps).
- **CLI:** `validate` and `certs check` with exit codes, for CronJobs and CI.

## Quick start

The fastest way to try it: API-key sign-in and a port-forward, in the integration's namespace.

```bash
# 1. An API key (printed once) and the entry for the keys file
docker run --rm ghcr.io/opswhisperer/eh-k8s-console new-api-key -name me -role admin 2>> api-keys.yaml

# 2. The console's Secret
kubectl create secret generic eh-k8s-console -n extrahop \
  --from-literal=session-secret="$(openssl rand -base64 48)" \
  --from-file=api-keys.yaml=./api-keys.yaml

# 3. Install and open it
kubectl apply -k 'https://github.com/opswhisperer/eh-k8s-console//deploy/base?ref=v0.1.2'
kubectl -n extrahop port-forward svc/eh-k8s-console 8080:80
curl -H "Authorization: Bearer <key from step 1>" http://localhost:8080/api/state
```

To try it with no write access at all, apply `deploy/examples/read-only` instead.

For browser sign-in, exposure through a Gateway or Ingress, annotation editing and alerts, start
from an example in [`deploy/examples`](deploy/examples) and follow
**[docs/install.md](docs/install.md)**.

## Security

- **Least privilege:** the console runs non-root on a read-only root filesystem, with every capability dropped. It gets only the RBAC it uses, and reads Secrets only by name. See [docs/install.md](docs/install.md#rbac).
- **No silent fallback:** it never runs without sign-in unless you choose `none` on a loopback address.
- **Secrets stay hidden:** secret values are never sent to the browser, logged or stored in its history.
- **Reporting vulnerabilities:** see [SECURITY.md](SECURITY.md).

## Develop

```bash
go test ./...
go run ./cmd/eh-k8s-console validate -context my-cluster      # one read-only check
go run ./cmd/eh-k8s-console serve -config dev.yaml            # see below
```

To run the UI against a cluster without changing it, use a `dev.yaml` with
`listen: 127.0.0.1:8088`, `readOnly: true` and `auth: {modes: [none]}`. The UI is plain
HTML, CSS and JS in [`web/static`](web/static), embedded in the binary, with no build step. See
[CONTRIBUTING.md](CONTRIBUTING.md).
